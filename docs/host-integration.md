# Rust host bridge integration

Integrated on `feat/bunker-foundation`: CLI, MCP routing, host scheduling, keyed metadata and mutation-boundary authorization are wired. Disposable Rust-to-built-Next/PostgreSQL mTLS enrollment, approval/deny/restore/replay fixtures pass. Live deployment and the remaining acceptance gaps below are separate.

```rust

```

CLI and MCP wiring is installed through `host --config PATH` and `mcp --host-config PATH`. Public API: enrollment/renewal with protected env/file token sources; configured mTLS transport; host policy/snapshot/evidence cycle; local metadata and frozen-plan request adapter; explicit one-time claim/execution. No approval tool. Daemon polling interval is 30 seconds. Do not expose tokens as CLI values. Host credential directory and durable consumed-marker directory must remain stable across restarts, owner-only, and outside restore destinations.

## Contract and constraints

Contract sources: `control-plane/INTEGRATION.md`, `control-plane/README.md`, `shared/openapi.yaml`, `control-plane/tests/identity.test.ts`, `control-plane/tests/next-gateway.test.ts`. No `production-identity.test.ts` exists in this checkout. Production has separate public enrollment HTTPS and mandatory-mTLS host HTTPS origins. Enrollment response chain is client identity chain, never server trust. Production requests send no human cookie, bearer, or gateway proof.

Core snapshots use 64-hex IDs; bridge maps these to tenant/host-scoped UUIDv5 IDs. Metadata only crosses the wire. The full exact plan, including local preview and destination, stays encrypted via `Repository::save_request`. Existing repository methods cannot update requests; a stable local create-once, fsynced marker will consume a server request before claim. Any ambiguous claim or crash requires a fresh request and human review. No automatic replay. Parent must preserve these markers, not treat them as disposable cache.

Repository exposes whole-snapshot and one-file restore, not session remapping, deletion, or arbitrary workspace merging. Expose only truthful supported modes. UI cannot generate an exact local plan via current endpoints; use a local CLI/MCP request entrypoint and review local redacted preview, then human approves metadata/digest through the UI. Endpoint proposals and final checks are recorded below.

## Implemented API for parent wiring

- `control_plane::HttpsOrigin::parse` accepts only a bare HTTPS origin; `/api` is added internally. No redirects, ambient proxies, cookies, human headers, or retry middleware. `ServerTrust::Native` loads OS roots; `CaBundle` replaces them with a separately supplied bundle. Enrolled `trustChain` validates/presents the **client identity only**.
- `CredentialStore::open` requires a canonical owner-only directory. `enroll(public_origin, &trust, expected_tenant, &EnrollmentTokenSource::{File,Environment}, &store)` generates P-256 locally, verifies CSR response bindings, and atomically persists one `identity.json`. CLI must accept token **file path/environment name**, never token values. Environment access is for an already protected process environment; the bridge does not mutate process-wide environment while threads may exist. File source rejects symlinks, hardlinks, group/world permissions, non-owner and oversized files.
- `host_service::ProductionHost::open(store, host_origin, trust)` loads the persisted identity. Its `cycle`, `request_restore`, and `execute_restore_once` refresh credentials in the last hour before expiry and rebuild mTLS. Renewal/expiry errors stop the operation. 401/403 latches that transport closed. A renewed leaf with less than one hour left (e.g. expiring issuer) stops work. Server backdates `notBefore` by 30 seconds; validation permits that while limiting remaining expiry to 24 hours.
- `LocalBindings::local_repository(&repo, storage_ref, key_ref)` pins local references to `repo.root()` and the actual encrypted repository header digest. Policy changes cannot select a different key/provider by relabeling. Parent's managed-key integration must add a verified binding adapter; the current bridge only accepts local repository storage with unrestricted residency. Header rewrap/rotation requires explicit rebinding. This does **not** advertise passphrase wrapping as a KMS implementation.
- `ProductionHost::cycle(&repo, &bindings, |policy| -> Result<WorkResults>)` is a 30-second authenticated policy tick. Work must not run if policy fetch/validation fails. Calls earlier than 30 seconds after a successful poll fail without invoking work. Configured remote-storage/DR policies use the [verified host storage adapter](host-storage.md) before success publication. Unsupported combinations and AU residency fail closed. End-of-session policy requires the explicitly enabled authenticated session handler and its durable receipt/outbox workflow; use `session-end` or `session-run` with `--host-config`. `retention_days` is available to explicit operator maintenance; host ticks never automatically delete backups.
- `WorkResults` accepts actual captured core snapshot IDs, observed alerts and explicit probe outcomes. Snapshot reporting verifies the repository before sending a succeeded report. Evidence uses explicit passed/failed/not_run outcomes with fixed reasons. The host persists exact evidence bodies before delivery, including skipped outcomes. Configured trusted container probes run on the effective restore-test interval; an unconfigured host reports not_run. See [restore probes](restore-probes.md).
- `ConsumedRequests::open(canonical_private_directory)` creates durable safety state. It must survive upgrades/restarts and must not be garbage-collected as cache. Use the same directory for all instances of a host. Plan records bind this path; passing another directory cannot reset a saved request. Use `ProductionHost` so credential and marker directories are excluded from restore destinations.
- `ProductionHost::request_restore(&repo, &consumed, core_snapshot, destination, selection)` is the MCP adapter and local CLI request entrypoint. `selection` is `Some(relative_file)` for a one-file restore or `None` for the complete snapshot restored in place. After creation, call `ProductionHost::local_restore_preview(&repo, local_request_id)` to print the exact saved redacted preview. Do not substitute a new `repo.plan` for human review: it might differ from the submitted plan. This helper makes no HTTP request. Never return its plan in MCP or send its content over HTTP. The digest to compare with the server is `RequestedRestore.diff_digest`, not the core plan’s internal `confirmation`. The result has `local_request_id`, `server_request_id`, `diff_digest`, `expires_at`; display these so the human can compare with UI metadata. The remote request may be created before any human preview, but the human must review the exact local plan before approval. The bridge persists an encrypted intent before creation and an encrypted exact plan + server ID after creation. Ambiguous creation is not retried; an orphan pending request expires on the server.
- `ProductionHost::execute_restore_once(&repo, &consumed, local_request_id)` is a separate trusted host action. It reads the encrypted frozen plan; verifies identity, digest, manifest, current destination and directory inode/device; consumes a fsynced create-once marker; fetches the exact server record; validates approved status, tenant, host, scope, changes and expiry; claims once; revalidates before invoking core restore with the exact confirmation. It rejects rebind-overwrite. Pending/denied/expired/ambiguous/bad claims stop. Any failure after consumption requires a **new** request and independent human review. Completion/audit failure never retries file writes. Calling execution too early consumes that request; parent should display/poll metadata first and invoke this action only for a matching locally saved request expected to be approved.
- `snapshot_files(&repo, identity, core_snapshot)` provides **local** file IDs, digests, sizes and executable flags. It contains no file paths or text. `HostIdentity::snapshot_id` is stable UUIDv5 scoped by tenant and host; session IDs are also scoped UUIDv5, never raw session labels. Paths, content hashes, manifests, plans and Git-state summaries use domain-separated repository-keyed metadata tokens; low-entropy content is not exposed as an unkeyed digest. A version field in the frozen plan binds serialization semantics.

Historical CLI design notes (use the current [CLI reference](user/cli.md) for exact flags): `host enroll --public-origin --host-origin --tenant --token-file/--token-env --server-ca-file --credential-dir`, `host run ...`, `host request-restore <snapshot> --destination ... [--file ...]`, `host execute-restore <local-request-id>`. Keep file-selection and destination control local. Do not expose approval/decision in MCP. Existing `request_restore` can call this adapter when configured; leave the old local approval execution disabled. Do not claim arbitrary session remapping, deletion or merge modes: only single file and whole snapshot restore are implemented.

## Required API revisions / remaining parent work

1. Current UI cannot create an exact local destination plan. Ship the local request entrypoint above; do not pretend the remote UI's selected files establish a valid local plan. A future host mailbox API needs an authenticated planning intent, host-returned metadata only, an opaque local plan handle, and independent human decision on its digest. Snapshot-file listing could accept `{snapshotId, manifestDigest, files:[{fileId,digest,bytes,executable}]}` with tenant/host ownership, limits and pagination. It must never include local paths/content or let the server choose an unchecked destination.
2. Implemented: evidence supports explicit `passed|failed|not_run` outcomes and bounded reasons. The durable host queue and trusted container runner are wired; real native-agent acceptance remains open.
3. Add a request-creation idempotency key/lookup endpoint if recoverable ambiguous creation is desired. There must remain no claim replay/reset endpoint. Completion reconciliation may verify an existing terminal state but must never re-execute.
4. Repository currently provides append-only encrypted request saving but no public update/list API. Consumed markers plus encrypted audit are the bridge's durable replay barrier. Parent may later move consumption into an encrypted repository transaction API with atomic `consume_if_pending`, while preserving cross-process exclusivity, directory fsync and permanent no-replay semantics. Do not simply overwrite a JSON status without a lock/atomic compare-and-set.
5. Core restore re-plans, verifies, stages and journals writes internally. The production bridge now supplies authorization checks at entry, after staging, Git mutation boundaries, and before every file install/chmod; checks bind the deadline and destination identity. An already-started syscall or Git subprocess cannot be preempted by the callback.
6. Credential-file protection currently supports Unix owner/mode semantics. Other platforms fail closed pending a Windows ACL implementation. Explicit protected-state migration/recovery is an administrator action, never automatic replay recovery. The identity store contains a local private key under filesystem protection, not a server-uploaded or plaintext-backup object.
7. The integrated Rust binary has passed the built Next/PostgreSQL/TLS gateway fixture for enrollment, policy, snapshot reporting, MCP request, human approval, restore, denial and replay refusal. Disposable fixture success does not establish live provider or operational CA acceptance.
