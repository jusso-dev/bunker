## Production identity increment (2026-10-29)

This section supersedes historical statements below that mTLS and federation are unimplemented. Scope: `control-plane/**`, `shared/openapi.yaml`, and `docs/adr/0003-production-identity.md`. No crates, deployment manifests, other docs, commits, pushes, deployments, PRs, or external messages were changed/sent by this increment. #26 remains deferred. Parent/root will independently council-review this implementation.

Implemented:
- Real Node/OpenSSL TLS gateway with separate public HTTPS and mandatory-client-certificate mTLS listeners; TLS validation is never disabled. Gateway upstream is numeric loopback only. Caller identity/forwarded headers are stripped. Every production API request needs a 30-second request-bound HS256 JWT (`jose`) and a globally one-use PostgreSQL nonce. Body, method, path/query, cookie, Origin, authorization, and content type are bound. Expiry is checked again after acquiring the nonce lock.
- Transactional one-use CSR enrollment using `@peculiar/x509`, client key possession through CSR signature and actual mTLS, server-assigned tenant/host SAN, recorded fingerprint identity, 24-hour maximum clientAuth certificates, host-preserving renewal by a currently authenticated host, and immediate application-layer revocation of every certificate for a host. Requested CSR identities/extensions are not trusted. Host private keys never reach the control plane.
- Configured generic OIDC suitable for pinned Entra tenant and Google issuers: HTTPS discovery, state, nonce, S256 PKCE, exact redirect/issuer/audience, RS256 JWKS signature and expiry verification through `oauth4webapi`. GitHub consumer OAuth is a separate fixed-endpoint flow using state/PKCE and numeric `/user` identity, not OIDC. Flow state is browser-bound, short-lived, and consumed even after a failed exchange.
- Explicit instance-admin identity link/unlink command, existing local session/RBAC/CSRF behavior, and configured provider buttons. Email/group claims cannot create accounts or grant roles. Unlink revokes all sessions and is serialized against in-flight callback session creation.
- Protected absolute regular-file references for CA/gateway/provider credentials; permissions, owner, size, URLs, and key properties fail closed. Incremental migration 002, API/OpenAPI/TypeScript updates, protocol, config example, and ADR are included.

Checks performed: security/client/config tests (7 reported tests); existing PostgreSQL integration regressions (13 reported tests); real TLS/PostgreSQL identity/provider fixtures (7 reported tests); and an actual built Next server behind both TLS gateway listeners (1 test). All passed without skips. Identity coverage includes CSR failure rollback and one-use concurrency, TLS missing/untrusted/wrong-purpose/expired certificates, unregistered certificate and wrong-tenant rejection, renewal, revocation, spoofed headers, body/path/header/signature tampering, replay/concurrent replay/expiry during nonce-lock waits, invalid OIDC signature/issuer/audience/nonce/expiry, unknown-subject and email auto-link rejection, flow expiry/reuse/browser binding, GitHub semantics, admin link/unlink CLI, and unlink/callback concurrency.
